# 评测系统启动与配置指南

[简体中文] · [English](../en/guidings/评测系统启动与配置指南.md) · [日本語](../ja/guidings/评测系统启动与配置指南.md)

本文说明如何配置并启动 Arcadegent 的评测工作台（`evaluate/`）：从零跑通一次冒烟评测、配置多个模型并发对比、开启 LLM judge 与人工复核，以及全部配置项的含义和默认值。评测的实现原理和指标定义见 [评测工作台架构与实现](../dev-details/评测工作台架构与实现.md)。

## 1. 评测有哪几种

| 模式 | 命令 | 是否调用真实模型 | 用途 |
| --- | --- | --- | --- |
| 离线契约回归 | `python -m evaluate check` | 否，禁止联网 | PR / CI 中检查协议与业务契约是否退化 |
| 在线模型评测 | `python -m evaluate validate / compatibility / run` | 是，产生 API 费用 | 比较模型在冻结用例上的表现 |
| 质量评分与复核 | `python -m evaluate grade / review / compare` | `grade` 调用 judge 模型，其余否 | 对已保存的运行重评、人工复核、对比 |

离线回归不需要任何配置；在线评测的配置都集中在 `evaluate/.env`。

## 2. 准备环境

需要 Python 3.11+。所有命令都在**项目根目录**执行。

```bash
python -m pip install -e './backend[dev]'
```

建议为评测单独建一个虚拟环境，例如：

```bash
python3.11 -m venv evaluate/.venv
evaluate/.venv/bin/python -m pip install -e './backend[dev]'
# 之后把下文的 python 换成 evaluate/.venv/bin/python，或先 source evaluate/.venv/bin/activate
```

`evaluate/.venv/` 已被 Git 忽略。

## 3. 离线契约回归

```bash
python -m evaluate check --suite contracts                      # 只跑 evaluate/checks
python -m evaluate check --suite backend                        # 再加上 backend/app/tests（默认）
python -m evaluate check --suite contracts -k native_tool_round_trip   # 按名称筛选
python -m evaluate check --suite contracts --output evaluate/reports/my-check
```

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--suite` | `backend` | `contracts` 或 `backend` |
| `-k` | 空 | 传给 pytest 的用例筛选表达式 |
| `--output` | `evaluate/reports/<时间戳-随机串>/` | 报告目录；相对路径以项目根目录为准；目录已存在时拒绝运行 |

测试期间所有 socket 连接都会被拒绝。设置 `ARCADEGENT_PUBLIC_CI=1` 会跳过依赖本地私有数据的用例（公开 CI 就是这样运行的）。退出码沿用 pytest；有任何跳过项时报告的 `complete` 为 `false`。

## 4. 在线评测：五分钟跑通冒烟

### 4.1 生成配置文件

```bash
python -m evaluate init-env
```

它把 `evaluate/.env.example` 复制为 `evaluate/.env`（权限 `0600`）。文件已存在时不会覆盖。

### 4.2 填写一个模型

打开 `evaluate/.env`，至少填写这四项：

```dotenv
EVAL_LLM_API_KEY=你的密钥
EVAL_LLM_BASE_URL=https://你的服务地址/v1
EVAL_LLM_MODEL=账号实际支持的模型ID
EVAL_LLM_API_MODE=chat_completions      # Responses 协议填 responses
```

- `BASE_URL` 不要带 `/chat/completions` 或 `/responses` 后缀，也不要在 URL 里放 key、query 或用户名密码。
- 协议必须显式指定，失败时不会自动切换到另一种协议。

### 4.3 检查、探测、运行

```bash
python -m evaluate validate        # 不调用模型：打印脱敏后的执行计划，检查缺失配置
python -m evaluate compatibility   # 每个 profile 最多 2 次真实请求，确认支持原生工具调用
python -m evaluate run             # 运行用例，默认是 3 个合成冒烟用例
```

运行结束后，终端会打印报告目录，打开其中的 `summary.md` 查看结果。各文件的含义见 [架构文档第 9 节](../dev-details/评测工作台架构与实现.md#9-证据与报告)。

## 5. 配置是怎么生效的

### 5.1 来源与优先级

从高到低：

1. 命令行参数（`--models`、`--cases`、`--repeat`、`--env-file`、`--output`）；
2. shell 中已设置的 `EVAL_*` 环境变量；
3. `--env-file` 指定的文件，默认 `evaluate/.env`；
4. 代码中的默认值。

只有以 `EVAL_` 开头的变量会被读取。项目根目录的 `.env` 和其他生产变量一律忽略，dotenv 也不做 `${VAR}` 插值。

### 5.2 相对路径

- `EVAL_CASES`、`EVAL_DATA`、`--cases` 中的相对路径以 `evaluate/` 目录为基准；
- `--output`、`--run`、`--env-file`、`--file`、`--baseline`、`--candidate` 中的相对路径以当前工作目录为基准；
- `check --output` 以项目根目录为基准。

### 5.3 模型 profile 的命名规则

`EVAL_MODELS` 是逗号分隔的 profile 名列表（小写字母开头，只含小写字母、数字、下划线，不能重复）。每个 profile 的变量前缀为：

| profile | 前缀 |
| --- | --- |
| `default` | `EVAL_LLM_` |
| 其他名字，如 `kimi` | `EVAL_KIMI_` |
| judge | `EVAL_JUDGE_` |

profile 之间**不互相继承**：给 `kimi` 设置温度或价格，不会影响 `default`，反之亦然。

## 6. 配置项参考

“代码默认”是变量未设置时的取值；“模板值”是 `.env.example` 中预填的值。两者不同时以你实际写入的值为准。

### 6.1 运行范围

| 变量 | 代码默认 | 模板值 | 说明 |
| --- | --- | --- | --- |
| `EVAL_MODELS` | `default` | `default` | 要评测的 profile 列表；可被 `--models` 覆盖 |
| `EVAL_CASES` | `datasets/public/smoke.yaml` | 同左 | 用例文件；可被 `--cases` 覆盖 |
| `EVAL_DATA` | `fixtures/arcades/synthetic.jsonl` | 同左 | 机厅数据 JSONL，必须与用例中的门店 ID 对应 |
| `EVAL_REPEAT` | `1` | `1` | 每个用例重复次数；可被 `--repeat` 覆盖 |

### 6.2 预算与超时

| 变量 | 代码默认 | 模板值 | 说明 |
| --- | --- | --- | --- |
| `EVAL_MAX_REQUESTS` | `40` | `40` | 本次运行所有模型共享的 Agent 请求总数上限 |
| `EVAL_MAX_CALLS_PER_ATTEMPT` | `40` | `40` | 单个 attempt 的模型请求上限（主 agent + worker），同时作为运行时的步数上限 |
| `EVAL_MAX_TOOL_CALLS` | `40` | `40` | 单个 attempt 的工具调用上限 |
| `EVAL_MAX_OUTPUT_TOKENS` | `32768` | `32768` | 每次 Agent 请求的输出 token 上限；太小会导致工具调用被截断（`finish_reason=length`） |
| `EVAL_REQUEST_TIMEOUT_S` | `45` | `45` | 单次 HTTP 请求超时，对所有 profile（含 judge）生效 |
| `EVAL_ATTEMPT_TIMEOUT_S` | `300` | `300` | 单个 attempt 的总超时；judge 单次评分也使用它 |
| `EVAL_REQUEST_INTERVAL_S` | `1` | `1` | 每次模型请求前的等待秒数，用于避开限流 |
| `EVAL_MAX_MODEL_CONCURRENCY` | `0` | `0` | 同时运行的模型 profile 数；`0` 表示所有 profile 一起跑。多个 profile 共用同一供应商账号时调小，避免触发限流 |

**全局预算怎么设**：多模型完整运行时，最坏情况的请求数是“模型数 × 用例数 × 重复次数 × 单 attempt 上限”。例如 4 个模型、38 个用例、重复 1 次、单 attempt 40 次，需要 `EVAL_MAX_REQUESTS=6080` 才能保证没有 attempt 因全局预算耗尽而未运行。这只是安全上限，实际请求数通常远小于此，也不是费用上限。

### 6.3 模型 profile

以下后缀适用于任意 profile 前缀（`EVAL_LLM_`、`EVAL_<NAME>_`、`EVAL_JUDGE_`）：

| 后缀 | 默认 | 说明 |
| --- | --- | --- |
| `API_KEY` | 空 | 必填 |
| `BASE_URL` | 空 | 必填；HTTP(S)，不含路径后缀、凭据、query |
| `MODEL` | 空 | 必填；账号实际可用的模型 ID |
| `API_MODE` | `chat_completions` | `chat_completions` 或 `responses` |
| `AUTH_HEADER` | `Authorization` | 鉴权头名称；部分服务需要如 `api-key` |
| `SEND_TEMPERATURE` | `true` | 服务不接受 temperature 时设为 `false` |
| `TEMPERATURE` | `0.2` | |
| `TOKEN_PARAMETER` | `max_tokens` | 部分服务需要 `max_completion_tokens` |
| `MAX_OUTPUT_TOKENS` | Agent 用 `EVAL_MAX_OUTPUT_TOKENS`；judge 为 `4096` | 单 profile 覆盖输出上限 |
| `EXTRA_PARAMETERS` | `{}` | 额外请求参数的 JSON 对象（如思考模式开关）；不能包含 `model`、`messages`、`input`、`tools`、`tool_choice`、`stream`、`instructions`、`headers` |
| `STREAM` | `false` | `true` 时以流式请求并在内部收集为完整响应，用于对比流式与非流式；判分逻辑不变 |
| `INPUT_PRICE` / `OUTPUT_PRICE` | 空 | 每百万 token 单价；不填则费用为 `null` |
| `CACHED_INPUT_PRICE` | 等于 `INPUT_PRICE` | 缓存命中的 input 单价 |
| `OFFPEAK_INPUT_PRICE` / `OFFPEAK_CACHED_INPUT_PRICE` / `OFFPEAK_OUTPUT_PRICE` | 空 | 可选的闲时价格，三项都填才生效；只影响报告中的闲时费用 |

### 6.4 LLM judge

| 变量 | 代码默认 | 说明 |
| --- | --- | --- |
| `EVAL_JUDGE_ENABLED` | `false` | 开启后必须填写完整的 `EVAL_JUDGE_*` profile |
| `EVAL_JUDGE_API_KEY` / `BASE_URL` / `MODEL` / `API_MODE` | — | 同 6.3，可以使用与被测模型不同的供应商 |
| `EVAL_JUDGE_MAX_REQUESTS` | `20` | judge 独立的请求预算，不占用 Agent 预算 |
| `EVAL_QUALITY_THRESHOLD` | `75` | 0–100；judge 分数达到它才算质量通过 |

### 6.5 地图与其他

| 变量 | 代码默认 | 模板值 | 说明 |
| --- | --- | --- | --- |
| `EVAL_MAP_MODE` | `disabled` | `disabled` | `live` 时导航用例调用真实高德路线服务 |
| `EVAL_AMAP_API_KEY` | 空 | 空 | 高德 Web 服务 key；建议使用评测专用 key |
| `EVAL_CURRENCY` | `unspecified` | `CNY` | 报告中的币种标签；所有 profile 的单价应使用同一币种 |

## 7. 常用场景

### 7.1 多模型并发对比

```dotenv
EVAL_MODELS=deepseek,glm,kimi
EVAL_DEEPSEEK_API_KEY=...
EVAL_DEEPSEEK_BASE_URL=...
EVAL_DEEPSEEK_MODEL=...
EVAL_GLM_API_KEY=...
EVAL_GLM_BASE_URL=...
EVAL_GLM_MODEL=...
EVAL_KIMI_API_KEY=...
EVAL_KIMI_BASE_URL=...
EVAL_KIMI_MODEL=...
# 可选：价格
EVAL_KIMI_INPUT_PRICE=...
EVAL_KIMI_OUTPUT_PRICE=...
```

不同 profile 的队列同时运行，同一 profile 内按用例顺序串行。如果几个 profile 共用同一个供应商账号，可以设置 `EVAL_MAX_MODEL_CONCURRENCY=1`（或更小的并发数）避免限流。也可以临时只选其中几个：

```bash
python -m evaluate run --models deepseek,kimi --repeat 3
```

缺少配置的 profile 不会报错中止，它的 attempt 会以 `missing_model_configuration` 记为未运行；`validate` 会对此返回退出码 2，建议先修好再运行。

### 7.2 运行完整开发集

开发集需要同时切换用例和数据：

```dotenv
EVAL_CASES=datasets/public/benchmark.yaml
EVAL_DATA=<本地地理编码机厅数据 JSONL，相对 evaluate/；路径示例见 .env.example 注释>
```

开发集有 38 个用例，其中 4 个导航用例只有在开启在线地图时才会运行：

```dotenv
EVAL_MAP_MODE=live
EVAL_AMAP_API_KEY=高德Web服务密钥
```

不开地图时导航用例记为 `live_map_not_configured`，累计加权完整通过分最高只能到 80（导航组占 20 分）。比较不同运行时，地图模式应保持一致。

### 7.3 开启 judge、重评与人工复核

```dotenv
EVAL_JUDGE_ENABLED=true
EVAL_JUDGE_API_KEY=...
EVAL_JUDGE_BASE_URL=...
EVAL_JUDGE_MODEL=...
EVAL_JUDGE_MAX_REQUESTS=50
EVAL_QUALITY_THRESHOLD=75
```

`EVAL_JUDGE_MAX_REQUESTS` 应不少于预计运行的 attempt 数，否则后面的 attempt 不会被评分。

```bash
# 对已保存的运行只重跑 judge（不重跑 Agent）
python -m evaluate grade --run evaluate/reports/<run_id>

# 人工复核
python -m evaluate review export --run evaluate/reports/<run_id>
#   编辑生成的 review-template.jsonl：填写 quality_pass（true/false）、reviewer、reason，evidence_refs 保留有效 ID
python -m evaluate review import --run evaluate/reports/<run_id> --file 复核结果.jsonl

# 对比两次运行（数据、用例、地图模式必须一致）
python -m evaluate compare --baseline evaluate/reports/<A> --candidate evaluate/reports/<B>
```

### 7.4 换一个配置文件

```bash
python -m evaluate run --env-file evaluate/.env.nightly --output evaluate/reports/nightly-01
```

`evaluate/.env*`（`.env.example` 除外）都被 Git 忽略，可以按场景保存多份配置。

### 7.5 推荐的配置组合

| 场景 | 建议 |
| --- | --- |
| 首次接入新模型 | 冒烟用例、`EVAL_REPEAT=1`、默认预算；先过 `compatibility` |
| 发布前多模型对比 | 开发集、`EVAL_REPEAT=3`、全局预算按最坏情况设置、开启在线地图、开启 judge |
| 校准 judge | 小批量运行，`review export` 人工复核后与 judge 结果对照，再调整 `EVAL_QUALITY_THRESHOLD` |
| 调试单个用例 | 复制一份只含该用例的 YAML，用 `--cases` 指定 |

## 8. 命令与退出码速查

| 命令 | 常用参数 | 退出码 |
| --- | --- | --- |
| `check` | `--suite`、`-k`、`--output` | 沿用 pytest |
| `init-env` | — | 0 |
| `validate` | `--env-file`、`--models`、`--cases`、`--repeat` | 0：配置完整；2：有 profile 或 judge 缺配置，或配置错误 |
| `compatibility` | 同上 + `--output` | 0：全部通过；1：有失败或未运行 |
| `run` | 同上 + `--output` | 0：全部完整通过；1：有未通过、未运行或未评分；2：配置错误；130：被 Ctrl+C 中断（已保存部分结果） |
| `grade` | 同上 + `--run`（必填） | 0：全部有效评分；1：有未完成评分 |
| `review export / import` | `--run`、`--file` | 0；校验失败时报错且不写入 |
| `compare` | `--baseline`、`--candidate` | 0；指纹不一致时报错 |

## 9. 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| `配置错误：EVAL_XXX_BASE_URL must be ...` | URL 带了路径后缀、query 或凭据，改成纯服务地址 |
| `评测未能完成：ValueError` | 用例或数据校验失败（门店 ID 不在数据中、YAML 格式错误等），或报告目录已存在。出于安全考虑只打印异常类型，请检查用例、数据路径与 `--output` |
| attempt 状态为 `budget_exhausted` | 单 attempt 的请求或工具调用超限；适当调高 `EVAL_MAX_CALLS_PER_ATTEMPT` / `EVAL_MAX_TOOL_CALLS` |
| 大量 `run_request_budget_exhausted` | 全局预算太小，按 6.2 的公式调高 `EVAL_MAX_REQUESTS` |
| 回答被截断、`finish_reason=length` | 调高 `EVAL_MAX_OUTPUT_TOKENS` 或该 profile 的 `MAX_OUTPUT_TOKENS` |
| 服务报 temperature 或 `max_tokens` 参数错误 | 设置 `SEND_TEMPERATURE=false`，或把 `TOKEN_PARAMETER` 改成 `max_completion_tokens` |
| 费用显示 `null` / 有未定价请求 | 没有填写单价，或供应商没有返回完整 usage；这类请求不会被当作免费 |
| judge 结果为 grader error | judge 输出不是合法 JSON、分数越界或引用了不存在的证据；可换更稳定的 judge 模型后用 `grade` 重评 |

## 10. 安全提醒

- `evaluate/.env` 只放评测专用的 key，不要复用生产 key。
- 报告目录会保存提示词、工具结果和回答，可能包含本地业务数据；`evaluate/reports/` 已被 Git 忽略，不要把报告提交或公开。
- 报告中的密钥、鉴权头和 URL query 中的 key/token 会被自动脱敏，但仍应把报告当作私有数据对待。
