# 本地工具编写与注册指南

[简体中文] · [English](../en/guidings/内建工具清单编写指南.md) · [日本語](../ja/guidings/内建工具清单编写指南.md)

> 2026-11（二级计划5 阶段 2b）起，机厅业务工具改为**代码注册**，本文按新结构重写。英文、日文版本仍描述旧的 manifest + `services` 结构，尚未同步。

本地工具（进程内执行、非 MCP 的工具）有两种注册方式：

| 方式 | 适用 | 本项目中的工具 |
| --- | --- | --- |
| **代码注册（推荐）**：在代码里构造 `ToolSpec`，由宿主调用 `ToolRegistry.add_tools(specs, services=...)` | 业务工具；需要宿主注入现成服务的工具 | `db_query_tool`、`geo_resolve_tool`、`route_plan_tool`、`summary_tool`、`result_selection_tool` |
| **manifest（可选）**：`BuiltinToolProvider` 读取 JSON manifest | agent 层自带的通用工具；需要保留能力（如 `spawn_agent`）的受信任配置 | `invoke_worker`、`list_skills`、`read_skill` |

相关代码：

- 业务工具：[`backend/app/domain/arcade/tools/`](../../backend/app/domain/arcade/tools/__init__.py)（`arcade_tool_specs()`、`arcade_tool_services(...)`）
- 组装：[`backend/app/core/container.py`](../../backend/app/core/container.py)

## 1. 代码注册

### 1.1 目录结构

```text
backend/app/domain/arcade/tools/
  __init__.py          # arcade_tool_specs() / arcade_tool_services(...)
  schemas/*.json       # 每个工具一份定义：name、description、input_schema、capabilities
  executors/*.py       # 每个工具的 execute / prepare_arguments
  *_tool.py            # executor 通过 ToolContext 取用的服务类（DBQueryTool、RoutePlanTool 等）
```

工具定义 JSON 只描述“工具是什么”，不写导入路径、环境变量或文件路径：

```json
{
  "name": "summary_tool",
  "kind": "function",
  "description": "Format a deterministic text summary from structured search or navigation context.",
  "capabilities": ["read_only", "summary", "concludes_turn"],
  "input_schema": {
    "type": "object",
    "properties": {
      "topic": { "enum": ["search", "navigation"], "type": "string" }
    },
    "required": ["topic"],
    "additionalProperties": false
  }
}
```

### 1.2 绑定 executor

`arcade_tool_specs()` 用 `ToolSpec.from_definition` 把 JSON 定义和 Python callable 绑在一起：

```python
ToolSpec.from_definition(
    SCHEMA_DIR / "summary_tool.json",
    executor=summary.execute,
    argument_preparer=summary.prepare_arguments,
)
```

- `executor`：`(context: ToolContext, args: dict) -> dict | ToolOutcome`，同步（在线程中执行）或异步均可。`args` 已通过 `input_schema` 校验并补齐默认值。
- `argument_preparer`：可选，`(raw_args, session_memory) -> (args, hydrated_fields)`，在校验前运行，用于从会话记忆补参。参数无法修复时抛 `ToolArgumentPreparationError`，消息会返回给模型，不要包含敏感值。
- 定义里如果还带 `executor`、`argument_preparer` 导入字符串，`from_definition` 会忽略它们；业务工具的 JSON 已删除这两个字段。

构造 `ToolSpec` 时即校验：名称格式（`[A-Za-z][A-Za-z0-9_-]{0,63}`，不能以 `mcp__` 开头）、描述非空、`input_schema` 根为 `{"type": "object"}` 且是合法的 JSON Schema 2020-12、`execution_mode` 只能是 `exclusive`/`parallel`。

### 1.3 服务

executor 通过 `context.require("名字")`（缺失时报错）或 `context.get("名字")`（缺失时返回 `None`）取用服务。服务由宿主构造，随工具一起注册：

```python
tool_registry.local_provider.add(
    arcade_tool_specs(),
    services=arcade_tool_services(store=store, amap_config=AMapConfig(...), mcp_tool_gateway=gateway),
)
```

- 配置值（例如 `AMAP_API_KEY`）由宿主从 `Settings` 读出后传入，工具代码不读环境变量。
- 同名服务绑定到不同对象会整批失败（`duplicate_service:<name>`）。
- container 在同步构建阶段直接写本地目录（`local_provider.add`）；运行中注册新工具用异步的 `await tool_registry.add_tools(...)`，它额外检查与 MCP 等其他 provider 的重名。

### 1.4 规则

- **注册不等于授权**：工具要出现在某个 agent 的工具定义里，仍需写进其 profile 的 `allowed_tools`，并符合工具策略。
- **保留能力**：运行时注册的工具不能声明 `spawn_agent`、`background`、`programmatic`（报 `reserved_capability:...`）；`concludes_turn` 可以使用。
- 运行时注册的工具可以 `update_tools`/`delete_tools`；manifest 工具不可以（报 `immutable_tool:...`）。

### 1.5 新增一个业务工具

1. 在 `domain/arcade/tools/schemas/` 下新建定义 JSON。
2. 在 `domain/arcade/tools/executors/` 下新建 executor 模块。
3. 在 `domain/arcade/tools/__init__.py` 的 `_BINDINGS` 里加一行；需要新服务时在 `arcade_tool_services` 里构造。
4. 在对应 agent 的 `allowed_tools` 中加入工具名。

## 2. manifest（可选方式）

`BuiltinToolProvider` 把 manifest 翻译成 `ToolSpec` 并以 `manifest` 来源装入目录。manifest 是受信任的宿主配置，可以声明保留能力，因此 `invoke_worker`（`spawn_agent`）仍走这条路。

### 2.1 manifest 文件

```json
{
  "tools": [
    "schemas/invoke_worker.json",
    "schemas/list_skills.json",
    "schemas/read_skill.json"
  ]
}
```

- 只允许 `tools` 一个键，值是工具定义文件路径（相对路径以 manifest 所在目录为基准）。
- 旧的 `services` 段（factory、`env`、`path`、`ref` 解析）已删除；manifest 中仍出现其他键时，加载报 `unsupported_builtin_tool_manifest_keys:<keys>`。

### 2.2 工具定义

在代码注册的字段之外，manifest 工具的定义还需要：

- `executor`：必填，导入路径，格式 `module.path:object_name`，例如 `app.agent.tools.builtin.executors.skills:list_skills`。缺少冒号报 `invalid_import_path`。
- `argument_preparer`：可选，格式同上。
- `metadata`：可选，原样复制为纯数据，不再解析 `path`/`env`/`ref`。运行时不读取 metadata。

### 2.3 服务

manifest 工具需要的服务同样由宿主传入：

```python
BuiltinToolProvider(services={"skill_registry": skill_registry})
```

`refresh()` 重新读取 manifest，只替换 `manifest` 来源的工具，运行时注册的工具保留。

## 3. `input_schema` 的写法

两种方式通用。运行时先按 schema 中的 `default` 补齐缺失字段，再做严格校验。建议：

- 可选字段显式写 `default`；
- 不允许额外字段时写 `additionalProperties: false`；
- 枚举约束直接用 `enum`。

只有当每个对象节点都声明 `additionalProperties: false` 且 `required` 覆盖全部属性时，发给模型的定义才会带 `strict: true`；本地校验始终按完整 schema 进行。
