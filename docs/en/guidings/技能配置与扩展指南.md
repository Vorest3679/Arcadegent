# Skill Configuration and Extension Guide

[简体中文](../../guidings/技能配置与扩展指南.md) · English · [日本語](../../ja/guidings/技能配置与扩展指南.md)

Arcadegent organizes skills according to the [Agent Skills specification](https://agentskills.io/specification) and follows the [official integration guide](https://agentskills.io/client-implementation/adding-skills-support)'s progressive loading flow: at startup or the beginning of a turn it discovers names and descriptions; after choosing a skill the model reads its body, and it reads reference resources only when needed. Skills do not need to be registered in a Python list or tools manifest.

## Add a Skill

The default directory is backend/app/agent/context/skills/. Create a direct child directory, for example:

```text
arcade-price-explanation/
├── SKILL.md
├── references/
│   └── pricing.md
├── scripts/             # optional; current runtime reads text but does not execute it
└── assets/              # optional; current reader accepts UTF-8 text only
```

Example SKILL.md:

```markdown
---
name: arcade-price-explanation
description: Explain arcade token and per-play prices. Use when a user asks about listed machine pricing.
metadata:
  author: arcadegent
  version: "1.0"
---

Read the current shop pricing and matching arcade fields.
See [pricing definitions](references/pricing.md) when distinguishing token price from per-play price.
Do not invent discounts that are absent from the observed results.
```

Fields follow the standard: name is required, at most 64 characters, and must match the directory name. Names use lowercase letters, digits, and hyphens; leading or trailing hyphens and repeated hyphens are not allowed. The official reference validator also supports Unicode letters and numbers with NFKC normalization. description is required, non-empty, and at most 1,024 characters. Optional fields are license, compatibility (1–500 characters), metadata (string-to-string mapping), and allowed-tools (space-separated string). Put extensions in metadata. Unknown top-level fields and duplicate YAML keys are rejected.

The Markdown body has no required section structure. The standard recommends fewer than 500 lines, but this project does not enforce a hard line limit. Resource paths are relative to the skill directory, not to the directory containing a referenced file.

The next user turn, worker execution, or list_skills call scans the directories and discovers additions, edits, and deletions. No code change or restart is needed; content already loaded in the current turn remains the same snapshot. Skills with the same name in multiple roots are isolated until the conflict is fixed and discovery refreshes.

## skill.config.py

backend/skill.config.py is a trusted project-level Python configuration file and must export config = SkillConfig(...). It is read at startup; restart the backend after editing it. Python files inside skill directories are not loaded as configuration. The file is loaded by path, so a dotted filename does not affect runtime behavior.

Example:

```python
from app.agent.skills.config import SkillConfig

config = SkillConfig(
    roots=["app/agent/context/skills", "../.agents/skills"],
    disabled_skills=["experimental-skill"],
    agent_skills={
        "search_worker": ["search-result-reading", "response-composition"],
        "navigation_worker": [],
    },
    max_file_bytes=64 * 1024,
    max_loaded_bytes=256 * 1024,
)
```

- Relative paths in roots are based on the directory containing skill.config.py. Multiple directories are supported; the operator's home directory is not scanned automatically.
- The default agent_skills={} makes all skills visible to every agent. If an agent appears in the mapping, only listed skills are allowed; an empty list means no skills. Global disabling takes precedence.
- Size limits count bytes in the original UTF-8 file; SKILL.md includes its frontmatter. Oversized files return an error instead of being truncated. Reading the same normalized relative path again is not charged twice.
- Docker builds include the configuration and default skill directory. For an external root, make those files available in the container or mount them.

These configuration, conflict-isolation, strict-validation, refresh, and size-limit rules are host policies, not fields in the generic Agent Skills format. The official integration guide allows permissive compatibility; this project validates strictly against the format. allowed-tools is parsed and retained but does not grant additional tool permissions. See [Skill Resource Directory Support](../dev-details/技能资源目录支持.md) for the detailed resource matrix and extension boundaries.

## How the Model Uses Skills

The base prompt describes the workflow. context_payload.directory.skills provides the current agent's available names and descriptions. Two tools are registered through the existing builtin manifest:

```text
list_skills({})
  → {"skills": [{"name": "search-result-reading", "description": "..."}]}

read_skill({"name": "search-result-reading"})
  → {"name": "search-result-reading", "path": "SKILL.md", "status": "loaded"}

read_skill({"name": "arcade-price-explanation", "path": "references/pricing.md"})
  → {"name": "arcade-price-explanation", "path": "references/pricing.md", "status": "loaded"}
```

If path is omitted, read_skill defaults to SKILL.md. After a successful read, the next model request includes the body or resource text in its loaded-skill-resources block; tool history stores only a receipt. Do not call list_skills again when the directory is already provided. Call it only when discovery needs a refresh.

The runtime binds the agent identity; the model cannot impersonate another agent through tool arguments. Reads are limited to text in available skills. Absolute paths, .., escaping symlinks, non-regular files, non-UTF-8 or binary content, and oversized content are rejected. Failed reads are not recorded as loaded, so the request can be corrected and retried.

## Module Boundaries and Migration

- SkillRegistry owns directory snapshots, standard metadata, and restricted reads; tools and context share it. Refresh is lock-protected and replaces the directory snapshot atomically. Invalid skills produce error codes without exposing YAML contents or local paths.
- SkillExecution stores the current turn's body and resource snapshot, not persistent working memory. The runtime uses task-local bindings for trusted agent identity and execution state; builtin executors obtain the registry through dependency injection.
- The main agent resets for each user turn, and each worker call starts with empty state. Worker results and serialized sessions do not include skill bodies; the main agent and workers do not inherit each other's loaded resources.
- ContextBuilder organizes the directory and resources loaded this turn. It does not discover files, enforce permissions, or execute them. Bodies are not copied into historical messages or recent tool results.

Migrate old skills/*.md files to skills/<name>/SKILL.md and replace underscores in names with hyphens. The old YAML skill_files and profile fields have been removed; old YAML fields now cause an explicit error and must move to skill.config.py. Replace ContextBuilder(skill_root=...) with an injected skill_registry.

Refresh is a cancellable asynchronous boundary: the runtime must save the user's input before waiting for directory refresh, or immediate cancellation could lose that input. Existing cancel-and-resume regression coverage checks this order.

## Verification Coverage

evaluate/checks/test_skills.py covers standard fields, dynamic create/update/delete, conflicts, allowlists, read boundaries, capacity limits, concurrent isolation, and serialization. API integration tests simulate a model and exercise skill discovery, body and reference loading, a business query, two worker executions, and reset on the next turn.

Run python -m pytest -q with the backend virtual environment. These checks do not require a real model; they verify runtime contracts and isolation, not the accuracy of a real model's skill selection.

At the time of the original change, backend/.venv/bin/python -m pytest -q from the repository root passed 264 tests, and git diff --check passed. Real-model skill-selection quality and Docker image builds were not tested.
