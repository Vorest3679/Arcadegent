# Evaluation System Setup and Configuration

[简体中文](../../guidings/评测系统启动与配置指南.md) · English · [日本語](../../ja/guidings/评测系统启动与配置指南.md)

This guide explains how to configure and start Arcadegent's evaluation workbench (`evaluate/`): running a first smoke evaluation from scratch, comparing several models concurrently, enabling the LLM judge and human review, and what every setting means and defaults to. For how the evaluation works and how metrics are defined, see [Evaluation Workbench: Architecture and Implementation](../dev-details/评测工作台架构与实现.md).

## 1. Kinds of evaluation

| Mode | Command | Calls real models? | Purpose |
| --- | --- | --- | --- |
| Offline contract regression | `python -m evaluate check` | No; network is blocked | Check in PRs / CI that protocol and business contracts have not regressed |
| Online model evaluation | `python -m evaluate validate / compatibility / run` | Yes; costs API money | Compare models on frozen cases |
| Quality grading and review | `python -m evaluate grade / review / compare` | `grade` calls the judge model; the others do not | Re-grade, review by hand, and compare saved runs |

Offline regression needs no configuration. All online configuration lives in `evaluate/.env`.

## 2. Prepare the environment

Python 3.11+ is required. Run every command from the **repository root**.

```bash
python -m pip install -e './backend[dev]'
```

A separate virtual environment for evaluation is recommended, for example:

```bash
python3.11 -m venv evaluate/.venv
evaluate/.venv/bin/python -m pip install -e './backend[dev]'
# then replace python below with evaluate/.venv/bin/python, or source evaluate/.venv/bin/activate first
```

`evaluate/.venv/` is ignored by Git.

## 3. Offline contract regression

```bash
python -m evaluate check --suite contracts                      # evaluate/checks only
python -m evaluate check --suite backend                        # plus backend/app/tests (default)
python -m evaluate check --suite contracts -k native_tool_round_trip   # filter by name
python -m evaluate check --suite contracts --output evaluate/reports/my-check
```

| Flag | Default | Meaning |
| --- | --- | --- |
| `--suite` | `backend` | `contracts` or `backend` |
| `-k` | empty | pytest selection expression |
| `--output` | `evaluate/reports/<timestamp-random>/` | Report directory; relative to the repository root; refused if it already exists |

All socket connections are refused during the tests. `ARCADEGENT_PUBLIC_CI=1` skips tests that need local private data (this is how public CI runs). The exit code is pytest's; any skipped test makes the report's `complete` `false`.

## 4. Online evaluation: a smoke run in five minutes

### 4.1 Create the config file

```bash
python -m evaluate init-env
```

This copies `evaluate/.env.example` to `evaluate/.env` (mode `0600`). An existing file is never overwritten.

### 4.2 Fill in one model

Open `evaluate/.env` and fill in at least these four:

```dotenv
EVAL_LLM_API_KEY=your-key
EVAL_LLM_BASE_URL=https://your-endpoint/v1
EVAL_LLM_MODEL=a-model-id-your-account-supports
EVAL_LLM_API_MODE=chat_completions      # use responses for the Responses protocol
```

- Do not add a `/chat/completions` or `/responses` suffix to `BASE_URL`, and do not put keys, queries or credentials in the URL.
- The protocol must be set explicitly; a failure never falls back to the other protocol.

### 4.3 Check, probe, run

```bash
python -m evaluate validate        # no model calls: prints the redacted plan and missing settings
python -m evaluate compatibility   # at most 2 real requests per profile to confirm native tool calls work
python -m evaluate run             # runs the cases; 3 synthetic smoke cases by default
```

When the run ends, the terminal prints the report directory; open `summary.md` inside it. For what each file contains, see [section 9 of the architecture note](../dev-details/评测工作台架构与实现.md#9-evidence-and-reports).

## 5. How configuration takes effect

### 5.1 Sources and precedence

Highest first:

1. Command-line flags (`--models`, `--cases`, `--repeat`, `--env-file`, `--output`);
2. `EVAL_*` variables already set in the shell;
3. The file given by `--env-file`, `evaluate/.env` by default;
4. Defaults in the code.

Only variables starting with `EVAL_` are read. The root `.env` and all other production variables are ignored, and dotenv does no `${VAR}` interpolation.

### 5.2 Relative paths

- Relative paths in `EVAL_CASES`, `EVAL_DATA` and `--cases` are relative to the `evaluate/` directory;
- Relative paths in `--output`, `--run`, `--env-file`, `--file`, `--baseline` and `--candidate` are relative to the current working directory;
- `check --output` is relative to the repository root.

### 5.3 Model profile naming

`EVAL_MODELS` is a comma-separated list of profile names (start with a lowercase letter; lowercase letters, digits and underscores only; no duplicates). Each profile's variable prefix is:

| Profile | Prefix |
| --- | --- |
| `default` | `EVAL_LLM_` |
| Any other name, e.g. `kimi` | `EVAL_KIMI_` |
| Judge | `EVAL_JUDGE_` |

Profiles **never inherit from each other**: setting a temperature or price for `kimi` does not affect `default`, and vice versa.

## 6. Settings reference

"Code default" is the value used when a variable is unset; "template value" is what `.env.example` pre-fills. When they differ, whatever you actually write wins.

### 6.1 Run scope

| Variable | Code default | Template value | Meaning |
| --- | --- | --- | --- |
| `EVAL_MODELS` | `default` | `default` | Profiles to evaluate; overridden by `--models` |
| `EVAL_CASES` | `datasets/public/smoke.yaml` | same | Case file; overridden by `--cases` |
| `EVAL_DATA` | `fixtures/arcades/synthetic.jsonl` | same | Arcade data JSONL; must contain the shop IDs used by the cases |
| `EVAL_REPEAT` | `1` | `1` | Repeats per case; overridden by `--repeat` |

### 6.2 Budgets and timeouts

| Variable | Code default | Template value | Meaning |
| --- | --- | --- | --- |
| `EVAL_MAX_REQUESTS` | `40` | `40` | Cap on agent requests shared by all models in the run |
| `EVAL_MAX_CALLS_PER_ATTEMPT` | `40` | `40` | Model requests per attempt (main agent + workers); also the runtime's step limit |
| `EVAL_MAX_TOOL_CALLS` | `40` | `40` | Tool calls per attempt |
| `EVAL_MAX_OUTPUT_TOKENS` | `1024` | `32768` | Output token cap per agent request; too small and tool calls get truncated (`finish_reason=length`) |
| `EVAL_REQUEST_TIMEOUT_S` | `45` | `45` | Timeout per HTTP request, for every profile including the judge |
| `EVAL_ATTEMPT_TIMEOUT_S` | `120` | `300` | Total timeout per attempt; also used for each judge call |
| `EVAL_REQUEST_INTERVAL_S` | `1` | `1` | Seconds to wait before each model request, to avoid rate limits |

**Sizing the global budget**: for a full multi-model run, the worst-case request count is models × cases × repeats × per-attempt limit. For example, 4 models, 38 cases, 1 repeat and 40 calls per attempt need `EVAL_MAX_REQUESTS=6080` to guarantee no attempt is skipped for lack of global budget. This is only a safety cap; actual requests are usually far fewer, and it is not a spending cap.

### 6.3 Model profiles

These suffixes apply to any profile prefix (`EVAL_LLM_`, `EVAL_<NAME>_`, `EVAL_JUDGE_`):

| Suffix | Default | Meaning |
| --- | --- | --- |
| `API_KEY` | empty | Required |
| `BASE_URL` | empty | Required; HTTP(S), no path suffix, credentials or query |
| `MODEL` | empty | Required; a model ID your account can use |
| `API_MODE` | `chat_completions` | `chat_completions` or `responses` |
| `AUTH_HEADER` | `Authorization` | Auth header name; some services need e.g. `api-key` |
| `SEND_TEMPERATURE` | `true` | Set `false` if the service rejects temperature |
| `TEMPERATURE` | `0.2` | |
| `TOKEN_PARAMETER` | `max_tokens` | Some services need `max_completion_tokens` |
| `MAX_OUTPUT_TOKENS` | agents: `EVAL_MAX_OUTPUT_TOKENS`; judge: `4096` | Per-profile output cap |
| `EXTRA_PARAMETERS` | `{}` | JSON object of extra request parameters (e.g. a thinking-mode switch); must not contain `model`, `messages`, `input`, `tools`, `tool_choice`, `stream`, `instructions` or `headers` |
| `STREAM` | `false` | `true` sends streaming requests and collects them into a full response, to compare streaming with non-streaming; grading is unchanged |
| `INPUT_PRICE` / `OUTPUT_PRICE` | empty | Price per million tokens; without them cost is `null` |
| `CACHED_INPUT_PRICE` | equals `INPUT_PRICE` | Price for cache-hit input |
| `OFFPEAK_INPUT_PRICE` / `OFFPEAK_CACHED_INPUT_PRICE` / `OFFPEAK_OUTPUT_PRICE` | empty | Optional off-peak prices; used only when all three are set; affect only the off-peak cost in reports |

### 6.4 LLM judge

| Variable | Code default | Meaning |
| --- | --- | --- |
| `EVAL_JUDGE_ENABLED` | `false` | When on, a complete `EVAL_JUDGE_*` profile is required |
| `EVAL_JUDGE_API_KEY` / `BASE_URL` / `MODEL` / `API_MODE` | — | As in 6.3; may be a different provider from the tested model |
| `EVAL_JUDGE_MAX_REQUESTS` | `20` | The judge's own request budget, separate from the agent budget |
| `EVAL_QUALITY_THRESHOLD` | `75` | 0–100; a judge score at or above this is a quality pass |

### 6.5 Maps and other settings

| Variable | Code default | Template value | Meaning |
| --- | --- | --- | --- |
| `EVAL_MAP_MODE` | `disabled` | `disabled` | `live` makes navigation cases call the real AMap route service |
| `EVAL_AMAP_API_KEY` | empty | empty | AMap Web service key; an evaluation-only key is recommended |
| `EVAL_CURRENCY` | `unspecified` | `CNY` | Currency label in reports; all profile prices should use the same currency |

## 7. Common scenarios

### 7.1 Concurrent multi-model comparison

```dotenv
EVAL_MODELS=deepseek,glm,kimi
EVAL_DEEPSEEK_API_KEY=...
EVAL_DEEPSEEK_BASE_URL=...
EVAL_DEEPSEEK_MODEL=...
EVAL_GLM_API_KEY=...
EVAL_GLM_BASE_URL=...
EVAL_GLM_MODEL=...
EVAL_KIMI_API_KEY=...
EVAL_KIMI_BASE_URL=...
EVAL_KIMI_MODEL=...
# optional: prices
EVAL_KIMI_INPUT_PRICE=...
EVAL_KIMI_OUTPUT_PRICE=...
```

Each profile's queue runs at the same time; within a profile, cases run in order. You can also pick a subset for one run:

```bash
python -m evaluate run --models deepseek,kimi --repeat 3
```

A profile with missing settings does not abort the run; its attempts are recorded as `missing_model_configuration`. `validate` returns exit code 2 in that case, so fix it before running.

### 7.2 Running the full development set

The development set needs both cases and data switched:

```dotenv
EVAL_CASES=datasets/public/benchmark.yaml
EVAL_DATA=<local geocoded arcade JSONL, relative to evaluate/; see the comment in .env.example for an example path>
```

It has 38 cases; the 4 navigation cases run only with live map enabled:

```dotenv
EVAL_MAP_MODE=live
EVAL_AMAP_API_KEY=your-AMap-Web-service-key
```

Without the map, navigation cases are recorded as `live_map_not_configured`, and the cumulative weighted complete score can reach at most 80 (navigation is worth 20 points). Keep the map mode the same across runs you compare.

### 7.3 Enabling the judge, re-grading and human review

```dotenv
EVAL_JUDGE_ENABLED=true
EVAL_JUDGE_API_KEY=...
EVAL_JUDGE_BASE_URL=...
EVAL_JUDGE_MODEL=...
EVAL_JUDGE_MAX_REQUESTS=50
EVAL_QUALITY_THRESHOLD=75
```

`EVAL_JUDGE_MAX_REQUESTS` should be at least the number of attempts you expect to run, otherwise later attempts go ungraded.

```bash
# re-run only the judge on a saved run (the agent is not re-run)
python -m evaluate grade --run evaluate/reports/<run_id>

# human review
python -m evaluate review export --run evaluate/reports/<run_id>
#   edit review-template.jsonl: fill quality_pass (true/false), reviewer, reason; keep valid IDs in evidence_refs
python -m evaluate review import --run evaluate/reports/<run_id> --file reviews.jsonl

# compare two runs (data, cases and map mode must match)
python -m evaluate compare --baseline evaluate/reports/<A> --candidate evaluate/reports/<B>
```

### 7.4 Using another config file

```bash
python -m evaluate run --env-file evaluate/.env.nightly --output evaluate/reports/nightly-01
```

`evaluate/.env*` (except `.env.example`) is ignored by Git, so you can keep several configs for different scenarios.

### 7.5 Recommended combinations

| Scenario | Suggestion |
| --- | --- |
| First time with a new model | Smoke cases, `EVAL_REPEAT=1`, default budgets; pass `compatibility` first |
| Pre-release multi-model comparison | Development set, `EVAL_REPEAT=3`, global budget sized for the worst case, live map on, judge on |
| Calibrating the judge | Small run; review by hand with `review export`, compare with judge results, then adjust `EVAL_QUALITY_THRESHOLD` |
| Debugging one case | Copy a YAML containing only that case and pass it with `--cases` |

## 8. Commands and exit codes

| Command | Common flags | Exit code |
| --- | --- | --- |
| `check` | `--suite`, `-k`, `--output` | pytest's |
| `init-env` | — | 0 |
| `validate` | `--env-file`, `--models`, `--cases`, `--repeat` | 0: configuration complete; 2: a profile or the judge is incomplete, or a config error |
| `compatibility` | same + `--output` | 0: all passed; 1: some failed or did not run |
| `run` | same + `--output` | 0: all complete passes; 1: some failed, did not run or were not graded; 2: config error; 130: interrupted with Ctrl+C (partial results kept) |
| `grade` | same + `--run` (required) | 0: all validly graded; 1: some grading incomplete |
| `review export / import` | `--run`, `--file` | 0; errors without writing anything if validation fails |
| `compare` | `--baseline`, `--candidate` | 0; errors if fingerprints differ |

## 9. Troubleshooting

| Symptom | Cause and fix |
| --- | --- |
| `配置错误：EVAL_XXX_BASE_URL must be ...` | The URL has a path suffix, query or credentials; use the plain service address |
| `评测未能完成：ValueError` | Case or data validation failed (shop ID missing from data, bad YAML, ...), or the report directory already exists. For security only the exception type is printed; check the cases, data path and `--output` |
| Attempt status `budget_exhausted` | Per-attempt request or tool-call limit hit; raise `EVAL_MAX_CALLS_PER_ATTEMPT` / `EVAL_MAX_TOOL_CALLS` |
| Many `run_request_budget_exhausted` | Global budget too small; raise `EVAL_MAX_REQUESTS` using the formula in 6.2 |
| Truncated answers, `finish_reason=length` | Raise `EVAL_MAX_OUTPUT_TOKENS` or the profile's `MAX_OUTPUT_TOKENS` |
| The service rejects temperature or `max_tokens` | Set `SEND_TEMPERATURE=false`, or change `TOKEN_PARAMETER` to `max_completion_tokens` |
| Cost is `null` / there are unpriced requests | No prices set, or the provider returned incomplete usage; such requests are not treated as free |
| Judge result is a grader error | The judge output was not valid JSON, the score was out of range, or it cited nonexistent evidence; switch to a more reliable judge model and re-grade with `grade` |

## 10. Security reminders

- Put only evaluation-specific keys in `evaluate/.env`; do not reuse production keys.
- Report directories keep prompts, tool results and answers and may contain local business data. `evaluate/reports/` is ignored by Git; do not commit or publish reports.
- Keys, auth headers and key/token values in URL queries are redacted in reports automatically, but still treat reports as private data.
