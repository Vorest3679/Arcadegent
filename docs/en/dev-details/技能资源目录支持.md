# Skill Resource Directory Support

[简体中文](../../dev-details/技能资源目录支持.md) · English · [日本語](../../ja/dev-details/技能资源目录支持.md)

Arcadegent follows the [Agent Skills directory convention](https://agentskills.io/specification): each skill is a directory containing `SKILL.md`, and may also include `scripts/`, `references/`, `assets/`, and other files or directories.

This document describes what the host runtime actually supports. The Agent Skills standard defines how directories and files are organized; it does not require a host to provide a script runner, binary asset transfer, or any particular tool name.

## Current Support Matrix

| Path | Standard purpose | Current status | Read behavior |
| --- | --- | --- | --- |
| `SKILL.md` | Metadata and skill instructions | Supported | Frontmatter is read during discovery; Markdown body is read when activated |
| `references/` | On-demand reference material | Supported | `read_skill(name, path="references/...")`; UTF-8 text |
| `scripts/` | Executable scripts shipped with a skill | Directory is accepted; execution is disabled | Script text can be read, but is not executed or imported and gains no tool permissions |
| `assets/` | Static resources such as templates, images, and data | Directory is accepted; text reading is supported | UTF-8 text only; binary files return a safe error |
| Other files/directories | Custom resources defined by skill authors | Text reading is supported | Normalized relative paths under the skill root |

The following layout can therefore be discovered directly:

```text
skill-name/
├── SKILL.md
├── scripts/
│   └── extract.py
├── references/
│   └── REFERENCE.md
├── assets/
│   ├── template.txt
│   └── example.json
└── examples/
    └── output.md
```

Discovery scans only the direct children of configured roots and looks for a file named exactly `SKILL.md`. Resource directories do not appear as separate skills. After activating a skill, the model reads its resources by using the same skill name and a relative path.

## Shared Security Boundaries

All resources pass through `SkillRegistry`:

- Paths must be relative to the skill root. Absolute paths, `..`, Windows path syntax, escaping symlinks, and non-regular files are rejected.
- Files must be valid UTF-8 text. Binary control characters, FIFOs, and content larger than `max_file_bytes` are rejected.
- Each agent run is limited by `max_loaded_bytes`. Re-reading the same skill and normalized path uses the current-turn snapshot and is not charged again.
- Resource reads follow agent allowlists and global disable rules. The `allowed-tools` frontmatter is retained as standard metadata and does not expand Arcadegent tool permissions.
- `SkillExecution` stores bodies and resources loaded during the current turn. Source text is not written to persistent sessions, tool history, or worker result envelopes.

## Reserved Extension Points

If full support for executable or binary resources is needed later, extend the existing `SkillRegistry` / `SkillExecution` boundary. Do not give the model direct filesystem access:

1. **Script runner:** Add an explicit `run_skill_script` capability with script and interpreter allowlists, a timeout, output-size limits, an isolated working directory, and network/filesystem policies. `allowed-tools` may participate in declaration and filtering, but cannot authorize execution by itself.
2. **Binary assets:** Add a separate `read_skill_asset` return type that distinguishes UTF-8 text, images, audio, and other binary data, with MIME, size, and transfer limits. Keep the `read_skill` text contract unchanged.
3. **Resource index:** Add a restricted resource index to discovery records or expose `list_skill_resources` after activation so the model does not have to guess paths. The index must not reveal the host's absolute skill-root path.
4. **Versions and caching:** Add a content hash and skill-snapshot version to `SkillResource` so script output, binary assets, and long-running tasks can be audited against the same snapshot.
5. **Trust policy:** Configure trust separately for project-, user-, and organization-level roots. Untrusted roots should expose metadata only by default; activation and execution require explicit authorization.

These capabilities are not part of the current default behavior. New resource types must preserve backward compatibility with the text-based `read_skill` interface and add contract tests for path safety, permissions, size limits, cancellation, and worker isolation.

## Author Guidance

Skill authors can already create complete standard directories and reference resources with relative paths in `SKILL.md`. For the current runtime, save material that the model needs to read as UTF-8 text. Treat scripts as source reserved for a future runner, and treat images, audio, and other binary assets as future-capability placeholders; do not assume the model can read them today.

See the [Skill Configuration and Extension Guide](../guidings/技能配置与扩展指南.md) for the standard format and configuration.
