# スキルのリソースディレクトリ対応

[简体中文](../../dev-details/技能资源目录支持.md) · [English](../../en/dev-details/技能资源目录支持.md) · 日本語

Arcadegent は [Agent Skills のディレクトリ規約](https://agentskills.io/specification)に従います。各スキルは `SKILL.md` を含むディレクトリで、`scripts/`、`references/`、`assets/` やその他のファイル・ディレクトリを含めることができます。

この文書では、ホストランタイムが実際に対応している範囲を説明します。Agent Skills 標準はディレクトリとファイルの構成を定めますが、スクリプト実行器、バイナリアセット転送、特定のツール名をホストに要求するものではありません。

## 現在の対応状況

| パス | 標準上の用途 | 現在の状態 | 読み取り方法 |
| --- | --- | --- | --- |
| `SKILL.md` | メタデータとスキル指示 | 対応済み | 検出時に frontmatter を読み、スキル有効化時に Markdown 本文を読む |
| `references/` | 必要に応じて読む参考資料 | 対応済み | `read_skill(name, path="references/...")`。UTF-8 テキスト |
| `scripts/` | スキルに付属する実行可能スクリプト | ディレクトリは許可、実行は無効 | スクリプト本文の読み取りは可能。実行・import はせず、ツール権限も付与しない |
| `assets/` | テンプレート、画像、データなどの静的リソース | ディレクトリは許可、テキスト読み取りに対応 | UTF-8 テキストのみ。バイナリは安全なエラーを返す |
| その他のファイル/ディレクトリ | スキル作者が定義するリソース | テキスト読み取りに対応 | スキルルートからの正規化済み相対パスを使用 |

たとえば、次の構成をそのまま検出できます。

```text
skill-name/
├── SKILL.md
├── scripts/
│   └── extract.py
├── references/
│   └── REFERENCE.md
├── assets/
│   ├── template.txt
│   └── example.json
└── examples/
    └── output.md
```

検出時に走査するのは、設定されたルートの直下のディレクトリだけです。ファイル名が `SKILL.md` と完全一致するものを探します。リソースディレクトリ自体は独立したスキルとして表示されません。モデルはスキルを有効化した後、同じスキル名と相対パスを使ってリソースを読みます。

## 共通のセキュリティ境界

すべてのリソースは `SkillRegistry` を経由します。

- パスはスキルルートからの相対パスでなければなりません。絶対パス、`..`、Windows パス構文、ルート外へ抜けるシンボリックリンク、通常ファイル以外は拒否します。
- 有効な UTF-8 テキストのみ許可します。バイナリ制御文字、FIFO、`max_file_bytes` を超える内容は拒否します。
- 1 回の Agent 実行には `max_loaded_bytes` の上限があります。同じスキルと正規化済みパスを再度読んだ場合は、同じターンのスナップショットを使い、再計上しません。
- リソース読み取りには Agent の許可リストと全体の無効化ルールが適用されます。`allowed-tools` frontmatter は標準メタデータとして保持しますが、Arcadegent のツール権限を拡張しません。
- `SkillExecution` は現在のターンで読み込んだ本文とリソースを保持します。元のテキストを永続セッション、ツール履歴、worker の結果 envelope には保存しません。

## 将来の拡張ポイント

標準ディレクトリの実行可能ファイルやバイナリを完全に扱う必要が生じた場合は、モデルにファイルシステムへの直接アクセスを許さず、既存の `SkillRegistry` / `SkillExecution` 境界を拡張します。

1. **スクリプト実行器：** 明示的な `run_skill_script` を追加し、スクリプトとインタープリターの許可リスト、タイムアウト、出力サイズ制限、作業ディレクトリの隔離、ネットワーク/ファイルシステムのポリシーを設けます。`allowed-tools` は宣言やフィルタリングに使えますが、それだけで実行を許可してはいけません。
2. **バイナリアセット：** UTF-8 テキスト、画像、音声、その他のバイナリを区別する `read_skill_asset` 専用の戻り値型を追加し、MIME、サイズ、転送量を制限します。`read_skill` のテキスト契約は変更しません。
3. **リソース索引：** 検出記録に制限付き索引を追加するか、有効化後に `list_skill_resources` を提供し、モデルがパスを推測しなくてよいようにします。索引からホスト上の絶対スキルルートを漏らしてはいけません。
4. **バージョンとキャッシュ：** `SkillResource` に内容ハッシュとスキルスナップショットのバージョンを追加し、スクリプト出力、バイナリアセット、長時間タスクを同じスナップショットに対応付けて監査できるようにします。
5. **信頼ポリシー：** プロジェクト、ユーザー、組織それぞれのルートに信頼度を設定します。信頼されていないルートは既定でメタデータだけを表示し、有効化と実行には明示的な許可を求めます。

これらは現在の既定動作には含まれません。新しいリソース型を追加する場合は、テキスト用 `read_skill` の後方互換性を保ち、パス安全性、権限、サイズ、キャンセル、worker 隔離の契約テストを追加してください。

## スキル作者向けガイド

スキル作者は標準のディレクトリ構成を今すぐ作成し、`SKILL.md` から相対パスでリソースを参照できます。現在のランタイムでモデルに読ませる資料は UTF-8 テキストで保存してください。スクリプトは将来の実行器向けソース、画像・音声などのバイナリは将来機能用のプレースホルダーとして扱い、現時点でモデルが読めると想定しないでください。

標準形式と設定については、[スキル設定と拡張ガイド](../guidings/技能配置与扩展指南.md)を参照してください。
