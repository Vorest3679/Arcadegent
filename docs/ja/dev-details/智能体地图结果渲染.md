# Agent の地図結果を描画する

[简体中文](../../dev-details/智能体地图结果渲染.md) · [English](../../en/dev-details/智能体地图结果渲染.md) · 日本語

最終更新：2026-04-15

## 目的

バックエンドが地図関連 artifact をフロントエンドに公開する方法と、フロントエンドがそれを地図コンポーネントに読み込む方法を説明します。

現在の実装では、次の境界を守ります。

- Assistant 本文は引き続き Markdown として描画します。
- モデルが自由に出力する HTML / TSX から地図を作りません。
- バックエンドの構造化 artifact を、固定の React コンポーネントで描画します。

```text
assistant markdown text
  + structured map artifacts
  -> ChatPanel
  -> AgentMapCard
  -> AmapMapCanvas / AmapShopMarkers / AmapRouteOverlay / MapActionBar
```

## データの入口

フロントエンドが地図 artifact を受け取る経路は二つあります。

### 1. session detail から復元する

過去の session を開くとき、または session detail を再読み込みするとき、フロントエンドは GET /api/chat/sessions/{session_id} を呼びます。バックエンドの ChatSessionDetail には次の地図関連フィールドが含まれます。

```json
{
  "shops": [],
  "route": null,
  "client_location": null,
  "destination": null,
  "view_payload": null
}
```

App.tsx は mapArtifactsFromSession(detail) でこれを統一形式の ChatMapArtifacts に変換します。

```ts
type ChatMapArtifacts = {
  shops: ArcadeSummary[];
  route?: RouteSummary | null;
  client_location?: ClientLocationContext | null;
  destination?: ArcadeSummary | null;
  view_payload?: Record<string, unknown> | null;
  route_pending?: boolean;
};
```

route、destination、shops、view_payload のいずれかがある場合にのみ、artifact を activeMapArtifacts に保存します。

### 2. SSE による段階的な route event

ナビゲーション中、バックエンドは navigation.route_ready を送信します。data は RouteSummary として扱います。例：

```json
{
  "provider": "amap",
  "mode": "walking",
  "distance_m": 1280,
  "duration_s": 960,
  "origin": {
    "lng": 121.4,
    "lat": 31.2,
    "coord_system": "wgs84",
    "source": "client",
    "precision": "approx"
  },
  "destination": {
    "lng": 121.475,
    "lat": 31.228,
    "coord_system": "gcj02",
    "source": "route",
    "precision": "approx"
  },
  "polyline": [],
  "hint": null
}
```

App.tsx は coerceStreamRoute(envelope.data) で軽く検証し、成功すると route と route_pending: true を含む activeMapArtifacts を更新します。前の shops、client_location、destination を保持し、必要に応じて既定の view_payload を補います。これにより、最終的な assistant 本文より先に route card を表示できます。

assistant.completed の後、フロントエンドは session detail を再取得します。session の完全な artifact で pending 状態を置き換え、route_pending を false にします。

## バックエンド artifact の契約

### shops

候補店舗の地図 card に使います。各店舗には少なくとも source_id、name、address、city_name、geo.gcj02 座標を含めます。

```json
{
  "source_id": 101,
  "name": "Arcade One",
  "address": "Nanjing East Road",
  "city_name": "上海市",
  "geo": {
    "gcj02": {
      "lng": 121.475,
      "lat": 31.228,
      "coord_system": "gcj02",
      "source": "geocode",
      "precision": "approx"
    },
    "source": "geocode",
    "precision": "approx"
  }
}
```

フロントエンドが marker に使うのは geo.gcj02 だけです。geo.gcj02 のない店舗も一覧には残りますが、marker は描画しません。

### route

route card に使います。provider、mode、distance_m、duration_s、origin、destination、polyline、hint を含みます。

注意点：

- 高徳地図に表示する座標は gcj02 です。
- origin がブラウザー位置の場合、バックエンドは wgs84 を返すことがあります。フロントエンドは描画前に近似 gcj02 へ変換します。
- polyline が空の場合は、origin と destination から fallback の線を作ります。

### client_location

高徳ナビゲーション URI を作るときの出発点です。ブラウザー位置を表す WGS84 座標で、地図または URI で使用する前にフロントエンドが変換します。通常は lng、lat、accuracy_m、city、region_text を含みます。

### destination

route card に終点名と住所を表示し、優先する終点座標を選ぶために使います。destination.geo.gcj02 があれば高徳ナビの終点に使い、なければ route.destination にフォールバックします。

### view_payload

view_payload は軽量な表示指示であり、任意の HTML を格納するものではありません。推奨フィールド：

```json
{
  "version": 1,
  "scene": "agent_route",
  "title": "現在地から Arcade One までのルート"
}
```

scene は agent_candidates と agent_route に対応します。view_payload.scene がない場合、route があれば agent_route、そうでなく shops があれば agent_candidates と推測します。

## フロントエンドの描画経路

### 1. App.tsx

役割：

- session detail から ChatMapArtifacts を取り出す。
- SSE の navigation.route_ready から pending route artifact を先行して作る。
- activeMapArtifacts を ChatPanel に渡す。

主な state：

```ts
const [activeMapArtifacts, setActiveMapArtifacts] = useState<ChatMapArtifacts | null>(null);
```

### 2. ChatPanel.tsx

user / assistant の Markdown message は通常どおり描画します。mapArtifacts がある場合は assistant の返信の下に AgentMapCard を追加します。返信が streaming 中でも地図 card を先に表示できます。地図 card は本文を置き換えず、本文を補強します。

### 3. AgentMapCard.tsx

agent_candidates または agent_route を判定し、route 座標を正規化し、地図の中心、タイトル、副題、高徳への遷移 action を組み立て、下位の地図コンポーネントへ渡します。

候補店舗の scene：

```text
AgentMapCard
  -> AmapMapCanvas
  -> AmapShopMarkers
  -> MapActionBar
```

route の scene：

```text
AgentMapCard
  -> AmapMapCanvas
  -> AmapRouteOverlay
  -> MapActionBar
```

### 4. 地図の基本コンポーネント

- AmapMapCanvas は AMap JS API を読み込み、map instance を作成・破棄し、AmapRuntime を公開します。
- AmapShopMarkers は shops[*].geo.gcj02 から marker を描画し、選択状態に対応します。marker をクリックすると選択中の店舗を更新します。
- AmapRouteOverlay は route.polyline と route.origin / route.destination を描画します。GCJ02 以外の座標は先に正規化します。
- MapActionBar は「ブラウザーで開く」と「高徳アプリを開く」を描画します。

## Markdown の推奨方法

モデルに Markdown 内で <AgentMapCard ... /> を出力させないでください。任意 HTML を許すと React の型、座標変換、URI 作成の仕組みを迂回します。

Markdown 本文は読みやすいままにします。例：

```markdown
候補の店舗をいくつか見つけました。下に地図カードを表示します。
```

地図は同じ assistant turn に付属する構造化 artifact から描画します。

将来 Markdown で地図宣言を行う場合は、次のような許可リスト方式の code fence だけを受け付けます。

````markdown
```arcadegent-map
{
  "version": 1,
  "scene": "agent_route",
  "title": "現在地から Arcade One までのルート"
}
```
````

parser は arcadegent-map fence のみ認識し、JSON だけを許可し、view_payload または ChatMapArtifacts への補助データとしてのみ利用し、最終的には AgentMapCard に描画させます。HTML、JavaScript、style、任意のコンポーネント名は許可しません。Markdown の読みやすさを保ちながら、モデル出力による制御不能な地図描画を防げます。

## デバッグチェックリスト

地図 card が表示されないときは、次を確認します。

1. ChatSessionDetail に shops、route、destination、view_payload のいずれかがあるか。
2. App.tsx の activeMapArtifacts が空でないか。
3. ChatPanel が mapArtifacts を受け取っているか。
4. AgentMapCard が正しい scene を推測したか。
5. VITE_AMAP_WEB_KEY が設定されているか、テストで window.__ARCADEGENT_AMAP_MOCK__ が設定されているか。
6. 候補 marker の shop.geo.gcj02 があるか。
7. route.destination または destination.geo.gcj02 があるか。
