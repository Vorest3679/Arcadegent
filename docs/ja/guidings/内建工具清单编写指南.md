# 組み込みツールマニフェストの作成ガイド

[简体中文](../../guidings/内建工具清单编写指南.md) · [English](../../en/guidings/内建工具清单编写指南.md) · 日本語

このガイドは、組み込み動的ツールレジストリを保守する人向けです。主に次のファイルを説明します。

- [backend/app/agent/tools/builtin/tools_manifest.json](../../../backend/app/agent/tools/builtin/tools_manifest.json)
- [backend/app/agent/tools/builtin/schemas/db_query_tool.json](../../../backend/app/agent/tools/builtin/schemas/db_query_tool.json)

現在の構成では、すべてのツールを1つの大きな JSON に埋め込んだり、中央の schemas.py / handlers.py で各組み込みツールを列挙したりしません。プラグインシステムに近い考え方です。

1. tools_manifest.json は共有 services と読み込む tool JSON を宣言します。
2. 各ツールは、名前、説明、入力 schema、executor、metadata を記述した独自の JSON ファイルを持ちます。
3. 起動時に BuiltinToolProvider がこれらのファイルを組み立てます。

JSON に不慣れな場合は、次の4点を覚えてください。

- 文字列には二重引用符を使い、単一引用符は使いません。
- オブジェクトの各フィールドは "field": value の形です。
- 最後の項目以外は、項目の後ろにカンマを置きます。
- JSON にコメントはありません。説明は文書に書き、ファイルには入れません。

## 1. 全体構成

### 1.1 tools_manifest.json

manifest の基本形は次のとおりです。

```json
{
  "services": {
    "...": {}
  },
  "tools": [
    "schemas/db_query_tool.json",
    "schemas/route_plan_tool.json"
  ]
}
```

- services は共有ランタイム依存をどう構築するかを記述します。
- tools は読み込む tool JSON のパスを列挙します。通常は manifest からの相対パスです。

loader はまず services に従って依存サービスを組み立て、その後 tools の各 JSON を読み込み、組み込みツールとして登録します。

### 1.2 個別の tool JSON

最小例は次のとおりです。

```json
{
  "name": "summary_tool",
  "kind": "function",
  "description": "Format a deterministic text summary from structured search or navigation context.",
  "executor": "app.agent.tools.builtin.executors.summary:execute",
  "input_schema": {
    "type": "object",
    "properties": {
      "topic": {
        "enum": ["search", "navigation"],
        "type": "string"
      }
    },
    "required": ["topic"],
    "additionalProperties": false
  }
}
```

通常、組み込みツールの追加では、tools_manifest.json にパスを追加し、tool JSON を作成します。実行ロジックに専用処理が必要なら、該当する Python モジュールに executor も追加します。

## 2. services の記述

services は、キーがサービス名、値がサービス設定のオブジェクトです。

```json
{
  "services": {
    "amap_config": {
      "factory": "app.agent.tools.builtin.route_plan_tool:AMapConfig",
      "dependencies": {
        "api_key": {
          "env": "AMAP_API_KEY",
          "default": ""
        },
        "base_url": {
          "env": "AMAP_BASE_URL",
          "default": "https://restapi.amap.com"
        },
        "timeout_seconds": {
          "env": "AMAP_TIMEOUT_SECONDS",
          "default": 8.0,
          "cast": "float"
        }
      }
    }
  }
}
```

- factory（必須）：module.path:object_name 形式の import パス。
- dependencies（任意）：factory のコンストラクターに渡す引数。
- singleton（任意）：既定値は true。サービスを一度だけ生成してキャッシュします。

### 2.1 別の service を直接参照する

```json
{
  "dependencies": {
    "store": "store",
    "amap_config": "amap_config"
  }
}
```

store と amap_config は service 名として解決されます。

### 2.2 環境変数を読む

```json
{
  "dependencies": {
    "timeout_seconds": {
      "env": "AMAP_TIMEOUT_SECONDS",
      "default": 8.0,
      "cast": "float"
    }
  }
}
```

使用できるフィールドは env（環境変数名）、default（環境変数がない場合の値）、cast です。cast は int、float、bool、string に対応します。

### 2.3 明示的な参照を使う

```json
{
  "dependencies": {
    "project_root": {
      "ref": "project_root"
    }
  }
}
```

ref は service 名を直接文字列で指定する方法と似ていますが、ドット区切りのパスにも対応します。

```json
{
  "dependencies": {
    "base_url": {
      "ref": "settings.amap_base_url"
    }
  }
}
```

### 2.4 パスを解決する

```json
{
  "dependencies": {
    "prompt_path": {
      "path": "app/agent/context/skills/response-composition/SKILL.md",
      "base": "project_root",
      "as_string": true
    }
  }
}
```

- path：相対パスまたは絶対パス。
- base：相対パスの基準にする service。既定値は project_root。
- as_string：true なら文字列のパス、false なら Path オブジェクトを返します。

### 2.5 固定値を指定する

```json
{
  "dependencies": {
    "provider": {
      "value": "amap"
    }
  }
}
```

### 2.6 ネストしたオブジェクトと配列

値がオブジェクトまたは配列の場合、loader は内部にある ref、env、path、value も再帰的に解決します。

## 3. 個別の tool JSON を記述する

各 tool JSON は独立したオブジェクトです。

- name（必須）：登録後のツール名。重複できません。
- kind（任意）：現在は通常 function を指定します。
- description（必須）：モデルにツールの用途を伝える説明。
- executor（必須）：module.path:object_name 形式の Python callable。
- input_schema（必須）：モデルに公開し、ランタイム検証にも使う JSON Schema。
- capabilities（任意）：能力ラベルを表す文字列配列。
- metadata（任意）：追加情報。dependencies と同様の参照解決に対応します。

### executor の形式

形式は次のとおりです。

```text
module.path:object_name
```

例：app.agent.tools.builtin.executors.route_plan:execute、app.agent.tools.builtin.executors.summary:execute。コロン : がない場合、ランタイムは invalid_import_path を報告します。

## 4. input_schema の記述

input_schema には標準 JSON Schema を使います。現在の loader は、まず不足フィールドに default を適用し、その後 JSON Schema で厳密に検証します。

推奨事項：

- 任意フィールドには明示的な default を設定します。
- 余分なフィールドを許可しない場合は additionalProperties: false を設定します。
- 値を制限するには enum を使います。

default を含む例：

```json
{
  "input_schema": {
    "type": "object",
    "additionalProperties": false,
    "properties": {
      "sort_order": {
        "type": "string",
        "enum": ["asc", "desc"],
        "default": "desc"
      }
    }
  }
}
```

モデルが sort_order を省略すると、ランタイムは desc を補います。

## 5. ツール全体の例

次の例は、リポジトリの route_plan_tool に近いものです。

```json
{
  "name": "route_plan_tool",
  "kind": "function",
  "description": "Plan a route from origin to destination.",
  "executor": "app.agent.tools.builtin.executors.route_plan:execute",
  "capabilities": ["builtin", "read_only", "navigation"],
  "metadata": {
    "guide": {
      "path": "app/agent/context/skills/navigation-result-reading/SKILL.md",
      "base": "project_root",
      "as_string": true
    }
  },
  "input_schema": {
    "$defs": {
      "LocationArgs": {
        "type": "object",
        "additionalProperties": false,
        "properties": {
          "lng": { "type": "number" },
          "lat": { "type": "number" }
        },
        "required": ["lng", "lat"]
      }
    },
    "type": "object",
    "additionalProperties": false,
    "properties": {
      "provider": { "type": "string", "enum": ["amap", "google", "none"] },
      "mode": { "type": "string", "enum": ["walking", "driving"] },
      "origin": { "$ref": "#/$defs/LocationArgs" },
      "destination": { "$ref": "#/$defs/LocationArgs" }
    },
    "required": ["provider", "mode", "origin", "destination"]
  }
}
```

## 6. ツール追加の最小手順

1. [backend/app/agent/tools/builtin/tools_manifest.json](../../../backend/app/agent/tools/builtin/tools_manifest.json) の tools 配列に新しいファイルパスを追加します。
2. [backend/app/agent/tools/builtin/schemas](../../../backend/app/agent/tools/builtin/schemas) に tool JSON を作り、name、description、executor、input_schema を記述します。
3. 新しい共有依存が必要なら、manifest の services に factory と dependencies を追加します。
4. 専用の実行ロジックが必要なら、[backend/app/agent/tools/builtin/executors](../../../backend/app/agent/tools/builtin/executors) に executor モジュールを追加します。

## 7. 設計上のトレードオフ

この構成では、組み込みツールの追加時に中央の schemas.py や handlers.py を編集する必要がありません。tool schema 自体が JSON ファイルとなり、provider/plugin の自己記述定義に近づきます。ツールの説明、引数、実行入口も同じローカルな範囲にまとまります。

専用の実行ロジックには引き続き Python executor が必要です。ただし、そのコードは中央 handlers への登録ではなく、ツール固有のモジュールに置きます。これが分割による主な利点です。
