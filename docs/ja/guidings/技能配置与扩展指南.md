# Skill の設定と拡張ガイド

[简体中文](../../guidings/技能配置与扩展指南.md) · [English](../../en/guidings/技能配置与扩展指南.md) · 日本語

Arcadegent は [Agent Skills 仕様](https://agentskills.io/specification)に沿って skill を構成し、[公式の導入ガイド](https://agentskills.io/client-implementation/adding-skills-support)にある段階的な読み込み手順に従います。起動時またはターン開始時に名前と説明を検出し、モデルが skill を選んだ後に本文を読み、必要な場合だけ参考資料を読み込みます。skill を Python リストや tools manifest に登録する必要はありません。

## Skill の追加

既定のディレクトリは backend/app/agent/context/skills/ です。直下に子ディレクトリを作成します。

```text
arcade-price-explanation/
├── SKILL.md
├── references/
│   └── pricing.md
├── scripts/             # 任意。現在のランタイムはテキストを読めるが実行しない
└── assets/              # 任意。現在の読み取り機能は UTF-8 テキストのみ対応
```

SKILL.md の例：

```markdown
---
name: arcade-price-explanation
description: Explain arcade token and per-play prices. Use when a user asks about listed machine pricing.
metadata:
  author: arcadegent
  version: "1.0"
---

Read the current shop pricing and matching arcade fields.
See [pricing definitions](references/pricing.md) when distinguishing token price from per-play price.
Do not invent discounts that are absent from the observed results.
```

フィールドは標準に従います。name は必須で、64 文字以内、ディレクトリ名と一致する必要があります。名前には小文字、数字、ハイフンを使用し、先頭/末尾のハイフンや連続したハイフンは使えません。公式の参照バリデーターは Unicode の英数字と NFKC 正規化にも対応します。description は必須で、空でなく、1,024 文字以内です。任意フィールドは license、compatibility（1～500 文字）、metadata（文字列キーと値のマップ）、allowed-tools（空白区切りの文字列）です。拡張情報は metadata に置きます。トップレベルの未知フィールドと重複 YAML キーは拒否されます。

Markdown 本文に必須の章構成はありません。標準は 500 行未満を推奨しますが、このプロジェクトは行数をハード制限しません。リソースパスの基準は skill ディレクトリであり、参照ファイルがあるディレクトリではありません。

次のユーザーターン、worker 実行、または list_skills 呼び出しでディレクトリを再スキャンし、追加・変更・削除を検出します。コード変更や再起動は不要です。現在のターンですでに読み込んだ内容は同じスナップショットのままです。複数のルートに同名 skill がある場合は互いに隔離され、競合の修正後に検出を更新すると復帰します。

## skill.config.py

backend/skill.config.py は信頼されたプロジェクトレベルの Python 設定ファイルで、config = SkillConfig(...) を export する必要があります。起動時に読み込まれ、変更後はバックエンドを再起動します。skill ディレクトリ内の Python ファイルは設定として読み込みません。ファイルはパス指定で読み込むため、ファイル名のドットはランタイムに影響しません。

```python
from app.agent.skills.config import SkillConfig

config = SkillConfig(
    roots=["app/agent/context/skills", "../.agents/skills"],
    disabled_skills=["experimental-skill"],
    agent_skills={
        "search_worker": ["search-result-reading", "response-composition"],
        "navigation_worker": [],
    },
    max_file_bytes=64 * 1024,
    max_loaded_bytes=256 * 1024,
)
```

- roots の相対パスは skill.config.py のあるディレクトリを基準にします。複数のディレクトリを指定できます。操作者のホームディレクトリは自動走査しません。
- 既定の agent_skills={} では、すべての Agent がすべての skill を参照できます。マッピングに Agent がある場合は列挙された skill だけを許可し、空リストは skill なしを意味します。全体の無効化が優先されます。
- サイズ上限は UTF-8 の元ファイルのバイト数で数えます。SKILL.md は frontmatter も含みます。上限超過時は切り詰めずエラーを返します。同じ正規化済み相対パスの再読み込みは再計上しません。
- Docker build には設定と既定の skill ディレクトリが含まれます。外部ルートを追加する場合は、コンテナ内にファイルを用意するか mount してください。

これらの設定、競合分離、厳密な検証、更新タイミング、サイズ上限は Arcadegent のホストポリシーであり、Agent Skills 共通形式のフィールドではありません。公式導入ガイドは寛容な互換性を認めていますが、このプロジェクトは形式に対して厳密に検証します。allowed-tools は解析して保持しますが、既存 Agent のツール権限は増やしません。リソース対応の詳細は[スキルのリソースディレクトリ対応](../dev-details/技能资源目录支持.md)を参照してください。

## モデルによる Skill の使用

基本 prompt が手順を説明し、context_payload.directory.skills が現在の Agent で利用できる名前と説明を提供します。既存の builtin manifest には次の 2 つのツールが登録されています。

```text
list_skills({})
  → {"skills": [{"name": "search-result-reading", "description": "..."}]}

read_skill({"name": "search-result-reading"})
  → {"name": "search-result-reading", "path": "SKILL.md", "status": "loaded"}

read_skill({"name": "arcade-price-explanation", "path": "references/pricing.md"})
  → {"name": "arcade-price-explanation", "path": "references/pricing.md", "status": "loaded"}
```

path を省略した場合、read_skill は SKILL.md を既定値にします。読み込みに成功すると、次のモデル要求の loaded skill resources ブロックに本文またはリソーステキストが含まれます。ツール履歴には receipt だけを保存します。ディレクトリがすでに提示されている場合、list_skills を繰り返し呼ぶ必要はありません。検出情報を更新するときだけ呼び出します。

現在の Agent identity はランタイムが設定し、ツール引数で別の Agent になりすますことはできません。読み取り対象は利用可能な skill 内のテキストに限られます。絶対パス、..、ルート外へのシンボリックリンク、通常ファイル以外、UTF-8 でない内容やバイナリ、サイズ超過は拒否されます。失敗した読み取りは loaded として記録されないため、要求を修正して再試行できます。

## モジュール境界と移行

- SkillRegistry はディレクトリのスナップショット、標準メタデータ、制限付き読み取りを担当し、ツールと context で共有されます。更新は lock で保護し、ディレクトリのスナップショットを一括で置き換えます。無効な skill は YAML 内容やローカルパスを出さず、エラーコードを記録します。
- SkillExecution は現在のターンの本文とリソースのスナップショットを保持し、永続 working memory にはしません。ランタイムは task-local binding で信頼済み Agent identity と実行状態を渡し、builtin executor は dependency injection で registry を取得します。
- main agent はユーザーの各ターンでリセットし、worker 呼び出しは毎回空の状態から始めます。worker の結果やセッションのシリアライズに skill 本文は含めません。main agent と worker は互いの読み込み済みリソースを引き継ぎません。
- ContextBuilder はディレクトリ情報と今回読み込まれたリソースを整理するだけで、ファイル検出、権限確認、実行は担当しません。本文を過去のメッセージや直近のツール結果に重複して書きません。

旧 skills/*.md は skills/<name>/SKILL.md に移し、名前のアンダースコアをハイフンに変更します。旧 YAML の skill_files と profile フィールドは削除済みです。検出された場合は明確なエラーとなるため、skill.config.py に移行してください。ContextBuilder(skill_root=...) は skill_registry の注入に変更します。

更新処理はキャンセル可能な非同期境界です。ランタイムはディレクトリ更新を待つ前にユーザー入力を保存する必要があります。そうしないと、直ちにキャンセルされた際に入力が失われる可能性があります。既存の cancel/resume 回帰テストがこの順序を確認します。

## 検証範囲

evaluate/checks/test_skills.py は標準フィールド、動的な追加/変更/削除、競合、許可リスト、読み取り境界、容量、並行分離、シリアライズをカバーします。API 統合テストではモデルを mock し、実際のツール分配で skill の検出、本文と参照資料の読み込み、業務クエリ、2 回の worker 実行、次ターンでのリセットを確認します。

バックエンドの仮想環境で python -m pytest -q を実行します。これらの検証に実際のモデルは不要です。ランタイム契約と分離動作を確認しますが、実際のモデルが skill を正しく選べるかは評価しません。

元の変更時にはリポジトリルートで backend/.venv/bin/python -m pytest -q を実行し、264 件が成功しました。git diff --check も成功しました。実モデルによる skill 選択品質と Docker image build は検証していません。
